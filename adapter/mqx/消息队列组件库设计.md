# 消息队列组件库设计（最终版）

> mqx — Go 语言通用消息队列组件库，面向接口设计，统一封装 RabbitMQ / Kafka / RocketMQ / Redis Stream。
> 本文为最终设计方案，整合并收敛了前五版设计的讨论结果。

---

## 一、设计目标

1. **统一接口** — 提供 `MessageQueue` / `Publisher` / `Subscriber` 核心接口，覆盖 80% 常用场景
2. **面向接口，不面向实现** — 业务代码只依赖 `mqx.Publisher` / `mqx.Subscriber`，不 import 具体后端
3. **职责单一** — 每个类型/文件只做一件事：连接、发送、消费、转换、拓扑，边界清晰
4. **Option 模式扩展** — 可选能力（延时、事务、分区键）走 `PublishOption` / `SubscribeOption`，不支持的返回 `ErrNotSupported`
5. **配置不泄露** — 通用配置在 `mqx` 包，后端专属配置在子包构造函数中，不进入接口方法签名
6. **库不碰序列化** — `Message.Body = []byte`，调用方决定 JSON / Protobuf / MsgPack

## 二、核心接口

### 2.1 MessageQueue

```go
// MessageQueue 持有底层连接，Publisher / Subscriber 从它派生，共享连接。
type MessageQueue interface {
Publisher(opts ...PublishOption) (Publisher, error)
Subscriber(opts ...SubscribeOption) (Subscriber, error)
Ping(ctx context.Context) error
Close() error
}
```

**职责**：只管连接，不碰路由。RabbitMQ / Redis Stream 底层共享同一 TCP 连接；Kafka / RocketMQ 内部各自独立创建但对外透明。

### 2.2 Publisher

```go
// Publisher 发布消息。
// topic 在 Publish 时指定；路由键/分区键/延时通过 PublishOption 控制。
type Publisher interface {
Publish(ctx context.Context, topic string, msg *Message, opts ...PublishOption) error
PublishBatch(ctx context.Context, topic string, msgs []*Message, opts ...PublishOption) error
Close() error
}
```

**职责**：只管发消息，不关心谁收。内部处理 Publisher Confirm（RabbitMQ）、ACK 确认（Kafka）、刷盘策略（RocketMQ）、XADD（Redis Stream）。

### 2.3 Subscriber

```go
// Subscriber 订阅消息。Subscribe 阻塞运行直到 ctx 被取消。
// Handler 返回 nil = ACK，返回 error = NACK（触发重试 / DLQ）。
type Subscriber interface {
Subscribe(ctx context.Context, topic string, handler Handler, opts ...SubscribeOption) error
Close() error
}
```

**职责**：只管收消息 + ACK/NACK + DLQ。内部抹平 Push（RabbitMQ）和 Pull（Kafka/RocketMQ/Redis）的差异，对调用方统一为回调式消费。重试由 `mqx.Retry` 中间件负责。

### 2.4 Handler

```go
// Handler 处理收到的消息。
// 返回 nil → ACK（消息处理成功）
// 返回 error → NACK（触发 DLQ；重试由 mqx.Retry 中间件处理）
type Handler func(ctx context.Context, msg *Message) error
```

**职责**：只管业务逻辑。不需要感知 ACK/NACK 机制，不需要调用 `msg.Ack()`。

## 三、Message

```go
type Message struct {
ID        string            // 消息唯一标识（生产者可设幂等键，空则后端自动生成）
Key       string            // 路由键/分区键（消费端读取；生产端由 PublishOption.WithKey 覆盖）
Body      []byte            // 消息体（库不碰序列化，调用方自行 marshal）
Headers   map[string]string // 业务元数据（trace_id、content-type 等）
Timestamp time.Time         // 消息产生时间（零值时 Publisher 自动填充 time.Now()）
}
```

极简 5 字段。没有 `Ack()`/`Nack()` 方法（返回值驱动），没有 `Raw()` 方法（不鼓励绕过抽象）。

### 后端字段映射

| 字段 | RabbitMQ | Kafka | RocketMQ | Redis Stream |
|------|----------|-------|----------|-------------|
| `ID` | `MessageId` | record key / UUID | `msgId` | entry ID（`{ms}-{seq}`） |
| `Key` | `RoutingKey` | record key | sharding key | 忽略 |
| `Body` | `Body` | `Value` | `Body` | field `body` |
| `Headers` | `amqp.Table` → `map[string]string` | record headers | `Properties` | field `headers`（JSON） |
| `Timestamp` | `Timestamp` | `Timestamp` | `BornTimestamp` | 从 entry ID 解析 |

## 四、配置

### 4.1 PublishOption（单次发布覆盖）

```go
type PublishConfig struct {
Key     string            // 路由键 / 分区键
Headers map[string]string // 追加 headers（与 Message.Headers 合并）
Delay   time.Duration     // 延时投递，0 = 立即
Timeout time.Duration     // 单次发送超时
}

type PublishOption func(*PublishConfig)

func WithKey(key string) PublishOption {
return func(c *PublishConfig) { c.Key = key }
}

func WithHeaders(h map[string]string) PublishOption {
return func(c *PublishConfig) { c.Headers = h }
}

func WithDelay(d time.Duration) PublishOption {
return func(c *PublishConfig) { c.Delay = d }
}

func WithTimeout(d time.Duration) PublishOption {
return func(c *PublishConfig) { c.Timeout = d }
}
```

| Option | RabbitMQ | Kafka | RocketMQ | Redis Stream |
|--------|:---:|:---:|:---:|:---:|
| `WithKey` | ✅ routing key | ✅ partition key | ✅ sharding key | ❌ 忽略 |
| `WithDelay` | ⚠️ 需延迟插件 | ❌ `ErrNotSupported` | ✅ 原生 | ❌ `ErrNotSupported` |
| `WithHeaders` | ✅ AMQP headers | ✅ record headers | ✅ properties | ✅ map fields |
| `WithTimeout` | ✅ ctx 超时 | ✅ ctx 超时 | ✅ ctx 超时 | ✅ ctx 超时 |

### 4.2 SubscribeOption（单次订阅覆盖）

```go
type SubscribeConfig struct {
Group       string        // 消费者组名
Concurrency int           // 并发 goroutine 数，默认 1（串行）
Prefetch    int           // 预取数量（流控窗口），默认 1
DLQTopic    string        // 死信目标 topic，空 = 不启用
AutoAck     bool          // handler 返回 nil 时自动 ACK，默认 true
ClaimIdle   time.Duration // Redis Stream 消费者启动时 reclaim 闲置 pending 消息的最小空闲时间
}

type SubscribeOption func(*SubscribeConfig)

func WithGroup(group string) SubscribeOption {
return func(c *SubscribeConfig) { c.Group = group }
}

func WithConcurrency(n int) SubscribeOption {
return func(c *SubscribeConfig) { c.Concurrency = n }
}

func WithPrefetch(n int) SubscribeOption {
return func(c *SubscribeConfig) { c.Prefetch = n }
}

func WithDLQ(topic string) SubscribeOption {
return func(c *SubscribeConfig) { c.DLQTopic = topic }
}

func WithAutoAck(v bool) SubscribeOption {
return func(c *SubscribeConfig) { c.AutoAck = v }
}

func WithClaimIdle(d time.Duration) SubscribeOption {
return func(c *SubscribeConfig) { c.ClaimIdle = d }
}
```

| Option | RabbitMQ | Kafka | RocketMQ | Redis Stream |
|--------|----------|-------|----------|-------------|
| `WithGroup` | Queue Name | `group.id` | `consumerGroup` | consumer group name |
| `WithConcurrency` | N 个 channel consumer goroutine | N 个 goroutine 共享 ConsumerGroup | N 个 MessageListener | N 个 goroutine XREADGROUP |
| `WithPrefetch` | `QosPrefetch` | `max.poll.records` | `pullBatchSize` | `COUNT` |
| `WithDLQ` | 原生 DLX | 自建 retry topic | 原生死信 topic | 额外 stream |
| `WithAutoAck` | `autoAck` | `enable.auto.commit` | 自动 commit | 不调 XACK |
| `WithClaimIdle` | ❌ 忽略 | ❌ 忽略 | ❌ 忽略 | `XAutoClaim` idle duration |

> **注意**：`MaxRetries` 不在 `SubscribeConfig` 中。重试通过 `mqx.Retry` 中间件实现——将 `mqx.Retry(3)` 放入 `mqx.Chain` 即可。这种设计让重试策略（次数、退避）与消费逻辑解耦。

### 4.3 创建时默认配置

`Publisher()` 和 `Subscriber()` 直接接受 `...PublishOption` / `...SubscribeOption`，传入的选项成为该实例的默认值，每次 `Publish`/`Subscribe` 调用时自动应用，调用级选项可覆盖。

```go
// 创建时设置默认 topic 和 key
pub, _ := mq.Publisher(mqx.WithKey("default-key"))

// 调用时 topic 必传，key 默认使用 "default-key"，也可覆盖
pub.Publish(ctx, "orders", msg)                         // key = "default-key"
pub.Publish(ctx, "orders", msg, mqx.WithKey("custom"))  // key = "custom"
```

## 五、ACK 语义统一映射

| 行为 | RabbitMQ | Kafka | RocketMQ | Redis Stream |
|------|----------|-------|----------|-------------|
| handler 返回 `nil` + AutoAck=true | `Ack(deliveryTag)` | `CommitOffset()` | `Ack(msgId)` | `XACK` |
| handler 返回 `error` | `Nack(deliveryTag, requeue=false)` → DLX | 不 commit offset | 进重试 topic | XACK + 写死信 stream |
| handler panic | `Nack(requeue=false)` → DLX | 不 commit | 进死信 | pending 超时 reclaim |

> **说明**：handler 返回 error 时 adapter 直接执行 NACK+DLQ 逻辑，不再由 adapter 内部重试。重试能力由 `mqx.Retry` 中间件在 handler 外层提供——error 在到达 adapter 之前已被中间件重试。

## 六、topic 参数语义

**统一规则**：`topic` = 消息送达的目的地路由标识。Exchange 是基础设施拓扑，在后端专属 Config 中声明。

| 后端 | `topic` 含义 | 其他路由配置 |
|------|-------------|-------------|
| **Kafka** | Kafka topic name | — |
| **RocketMQ** | RocketMQ topic name | — |
| **Redis Stream** | Stream key | — |
| **RabbitMQ** | Routing key | Exchange 名/类型在 `rabbitmqx.Config` 声明 |

RabbitMQ 通配符订阅示例：

```go
sub.Subscribe(ctx, "order.*", handler, mqx.WithGroup("order-svc"))    // 匹配 order.created / order.paid
sub.Subscribe(ctx, "payment.#", handler, mqx.WithGroup("pay-svc"))    // 匹配 payment.* 及子级
```

## 七、连接共享策略

| 后端 | Publisher & Subscriber 共享连接 | 实现方式 |
|------|:---:|------|
| **RabbitMQ** | ✅ | 一个 `amqp.Connection` → 各自 `amqp.Channel` |
| **Kafka** | ❌ | `SyncProducer` / `ConsumerGroup` 类型不同，独立创建 |
| **RocketMQ** | ❌ | 生产者/消费者是不同实例 |
| **Redis** | ✅ | 一个 `go-redis` client 同时支持 `XADD` 和 `XREADGROUP` |

`MessageQueue` 内部根据后端类型决定共享还是独立创建，对外透明。

## 九、中间件

`Middleware` 类型和 `Chain` 组合子定义在 `mqx` 核心包中，所有中间件函数也位于 `mqx` 包。

```go
type Middleware func(Handler) Handler

// Chain 将多个中间件从左到右串联（第一个在最外层）
func Chain(middlewares ...Middleware) Middleware
```

内置中间件：

```go
// Retry — handler 返回 error 后线性退避重试（100ms → 200ms → 300ms → ...）。
// maxRetries=N 表示最多重试 N 次（总共最多 N+1 次尝试）。
// ctx 取消时立即返回，不再重试。
func Retry(maxRetries int) Middleware

// Recovery — catch handler panic，转为 error 返回，防止消费 loop 退出。
func Recovery(logger Logger) Middleware

// Logging — 记录每次消息处理的耗时和结果。
func Logging(logger Logger) Middleware

// 指标 — 上报消息量、延迟、错误率等
func Metrics(registry MetricsRegistry) Middleware
```

**定位**：重试、日志、panic 恢复都是横切关注点，全部走中间件。adapter 的 `handleXxx` 只负责 ACK/NACK/DLQ 等协议级确认，不处理重试逻辑。调用方通过 `mqx.Chain` 自由组合中间件顺序。

## 十一、使用示例

### 11.1 初始化

```go
import (
"github.com/xxx/mqx"
"github.com/xxx/mqx/rabbitmq"
)

// RabbitMQ
mq, err := rabbitmqx.New(&rabbitmqx.Config{
URL:          "amqp://user:pass@localhost:5672/",
ExchangeName: "orders",
ExchangeType: rabbitmqx.ExchangeTopic,
Reconnect: rabbitmqx.ReconnectConfig{
MaxRetries:   0,              // 0 = 无限重连
InitialDelay: 1 * time.Second,
MaxDelay:     30 * time.Second,
},
})
defer mq.Close()
```

### 11.2 发布消息

```go
pub, _ := mq.Publisher()
defer pub.Close()

body, _ := json.Marshal(order)
err := pub.Publish(ctx, "order.created", &mqx.Message{
ID:        uuid.New().String(),
Body:      body,
Headers:   map[string]string{"trace_id": traceID},
Timestamp: time.Now(),
}, mqx.WithKey("user-123"))

// 延时发布（RocketMQ 原生支持，RabbitMQ 需插件，其他后端返回 ErrNotSupported）
err := pub.Publish(ctx, "order.created", msg, mqx.WithDelay(30*time.Second))
```

### 11.3 订阅消息

```go
sub, _ := mq.Subscriber()
defer sub.Close()

err := sub.Subscribe(ctx, "order.#", func(ctx context.Context, msg *mqx.Message) error {
var order Order
if err := json.Unmarshal(msg.Body, &order); err != nil {
return err // NACK → DLQ
}
return processOrder(ctx, &order) // nil → ACK, err → NACK → DLQ
},
mqx.WithGroup("order-service"),
mqx.WithConcurrency(4),
mqx.WithPrefetch(100),
mqx.WithDLQ("order.dead"),
)
```

### 11.4 中间件使用

```go
// 用 Chain 组合多个中间件，从左到右执行
handler := mqx.Chain(
mqx.Recovery(logger),   // 最外层：catch panic
mqx.Logging(logger),    // 记录耗时
mqx.Retry(3),           // 最内层：线性退避重试
)(processOrder)

sub.Subscribe(ctx, "order.#", handler,
mqx.WithGroup("order-service"),
mqx.WithConcurrency(4),
mqx.WithDLQ("order.dead"),
)
```

## 十三、设计决策汇总

| # | 决策 | 说明 |
|---|------|------|
| 1 | MessageQueue 中介模式 | 持有连接，Publisher/Subscriber 从它派生，共享底层连接 |
| 2 | 直接构造 | `rabbitmqx.New(config)` 返回 `mqx.MessageQueue`，无需注册中心 |
| 3 | Publisher / Subscriber | 命名精准表达发布/订阅语义 |
| 4 | 返回值驱动 ACK | `Handler func(ctx, msg) error`，不暴露 Ack/Nack 方法 |
| 5 | Option 模式扩展 | 延时/分区键等能力走 PublishOption，不支持返回 ErrNotSupported |
| 6 | topic 在调用时传入 | MessageQueue 不管路由，职责单一 |
| 7 | group 在 SubscribeOption | ConsumerGroup 是消费侧概念，不属于连接层 |
| 8 | 后端专属构造 | 通用层不泄露后端细节，调用方只在构造时感知一次 |
| 9 | 中间件处理横切逻辑 | 重试、日志、panic 恢复统一走 `mqx.Chain` 中间件模式，adapter 只负责 ACK/NACK/DLQ 协议确认 |
